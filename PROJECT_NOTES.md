# SpendSense — Interview and Resume Notes

Factual project summary for interview preparation. Adapt claims to the exact role and keep resume statements consistent with the current implementation.

## Problem and stack

- Personal-finance application for managing transactions, budgets, analytics, reports, forecasts, recurring-spend signals, anomalies, and data-based insights.
- React + Vite frontend; Node.js + Express API; MongoDB + Mongoose; Python **FastAPI** ML service.
- The Node API is the source of truth for auth, authorization, transaction persistence, and financial calculations.

## Engineering decisions

- Kept the existing monolithic API and added the Python service only for ML tasks already present; no cache, queue, or additional infrastructure is required by current load.
- Used user-scoped MongoDB filters on private financial operations. Transaction listing supports server-side search/filter/sort/offset pagination with a capped page size.
- Added compound indexes for user/date and user/category/type/date transactions, a unique per-user budget/category index, and a unique per-user anomaly/transaction index.
- Used MongoDB aggregation for overview/category/trend/cash-flow summaries to avoid moving every matching transaction into Node.
- Kept existing numeric amount contracts. Summary responses round to two decimals; exact decimal accounting would require a planned schema migration.

## Important API and data flows

- Auth: `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`, `PUT /api/auth/change-password`. Passwords are bcrypt-hashed; JWTs use an environment-configured secret; password change increments a token version to revoke older tokens.
- Transactions: `GET/POST /api/transactions`, `PUT/DELETE /api/transactions/:id`, `POST /api/transactions/import-csv`. The server validates inputs, derives the owner from authenticated middleware, deduplicates CSV rows per user, and preserves an explicitly supplied category.
- Intelligence: `/api/analytics/*`, `/api/budgets`, `/api/forecast`, `/api/insights`, `/api/insights/anomalies`, `/api/insights/recurring`, and `/api/reports/monthly`.
- ML: Node sends categorization, anomaly, and forecast requests to FastAPI with bounded timeouts. Categorization, anomaly, and forecast logic have local fallbacks when the service is unavailable. Production ML routes require the shared `ML_API_KEY`.
- Insights combine authenticated transaction history, budgets, forecast calculations, and anomaly results. Anomaly records are unique by user and transaction and are upserted on refresh.

## Security and reliability

- Private route groups use JWT authentication; record updates/deletes and analytics are user-scoped.
- Environment validation rejects missing/weak JWT secrets and requires production database, CORS, ML URL, and ML key configuration.
- API errors avoid returning stack traces/database details. Request IDs, structured operation logs, body/file limits, and graceful server shutdown are present.
- CSV uploads have a 5 MB limit and 5,000-row processing cap. Demo seeding is opt-in, disabled in production, scoped to the configured demo account, and contains no default credentials.
- Existing browser tokens remain in Web Storage; multi-instance deployments need shared rate limiting.

## Testing and performance evidence

- Node's built-in test runner covers auth/password revocation, protected access, cross-user isolation, transactions, budgets, CSV validation/deduplication, aggregation/rounding, reports, recurring detection, insights, anomalies, and forecasts.
- Python unit tests cover anomaly history requirements and forecast projections.
- CI runs backend API tests against MongoDB, ML tests, and a frontend production build.
- Recent local verification: backend API tests pass both with ML unavailable and with a live local ML service; ML unit tests pass; the Vite build passes. Lint reports warnings and the frontend bundle exceeds the build's 500 KB warning threshold.
- The exact `npm test` count and build state should be refreshed after later code changes before using them as current resume evidence.

## Demo and deployment

- Opt-in demo seed produces three months of income and multi-category expense history, repeated subscription descriptions, a high-value current Food & Dining transaction, and budgets; forecasts, recurring signals, anomalies, and insights are generated by the normal API flows.
- Intended deployment split is static React frontend, Express API, FastAPI ML service, and managed MongoDB. The repository CI verifies but does not deploy.

## Honest limitations / discussion points

- Numeric storage is not exact-decimal accounting; migrating to integer minor units/Decimal128 requires backfill and API review.
- CSV duplicate preflight is not atomic for concurrent uploads; idempotency keys/fingerprints and a unique index are a future improvement.
- Substring search and deep offset pagination may need Atlas Search/cursor pagination at larger scale.
- Currency formatting is currently INR-oriented despite a USD profile option; values must not be combined across currencies.
- Anomaly and recurring behavior are heuristic/history-based, and forecasts are estimates rather than guarantees.
